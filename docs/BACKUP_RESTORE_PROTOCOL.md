# Synthetic Review Backup and Restore Protocol

This is an **experimental primitive for a synthetic MongoDB loopback fixture only**. It is not a production backup solution and does not connect to Atlas. It has no CLI, web route, credential configuration, or general cleanup function. `scripts/review_backup.py` accepts only `mongodb://127.0.0.1:<port>/?directConnection=true`, with no authentication, database, or other parameters. After connecting, it requires the `codex-review-test` replica-set primary. The source must be named `review_backup_src_<uuid4-hex>`, and the target must be named `review_backup_dst_<uuid4-hex>`. Tunneling the connection or pointing the fixture at a real system is outside the permitted scope.

## Contents and limits

`seal_snapshot(documents, indexes, key)` creates a Fernet token containing BSON version 1, a UTC creation time, the review documents, and exactly two indexes: unique `(owner, key)` and TTL `expires_at=0`. MongoDB creates the `_id` index. `snapshot_fixture(uri, source_name, key)` reads the synthetic `reviews` collection through a snapshot transaction and encrypts it. The source may contain only that collection, and the indexes must match the contract. Indexes are checked before the snapshot transaction, so the fixture must be exclusive; do not change indexes concurrently. The primitive does not back up `limits`, `api_limits`, or `review_guard`; this is not a full snapshot of an application database.

`restore_fixture(uri, target_name, ciphertext, key)` validates Fernet, decrypts the payload, and checks the complete BSON/schema/version, duplicate IDs, duplicate owner/key pairs, duplicate or incorrect indexes, and size limits **before connecting or creating the target**. The target must not already exist; overwriting is not supported. Records with `expires_at` earlier than or equal to the restore time are skipped. Unexpired records retain their original expiry, `_id`, owner, and key; review IDs derived from owner/key therefore remain stable. Records that expire during restore are not extended; API reads must continue to filter by expiry, and TTL cleanup happens later. Indexes are created before records are inserted in a transaction. If an error occurs after collection creation, the synthetic target may remain empty and require investigation; it is not deleted automatically for a retry.

Fixed limits: at most 500 documents, 32,768 bytes per document, 2,000,000 bytes of plaintext BSON, and 3,000,000 bytes of ciphertext; nested structures may be no more than 30 levels deep. Only BSON ObjectId `_id` values, 64-character hexadecimal owners, valid analysis/scene/selection keys, and expiry timestamps with exact UTC millisecond precision are accepted. Fixture types such as Binary, Int64, Decimal128, Timestamp, UTC datetime, arrays, and documents are supported. Unsupported types are rejected instead of being silently transformed. The conservative size check may reject a document smaller than MongoDB's actual BSON limit.

Encryption and authentication use [Fernet from pyca/cryptography](https://cryptography.io/en/latest/fernet/); the caller supplies the key as bytes. Do not write the key, URI, note, or plaintext digest to logs or receipts. The primitive does not write files and returns only token bytes. A restore receipt contains only the version and aggregate counts, not review contents. Fernet does not hide token creation time or length; anyone with the key can both decrypt and create tokens. This primitive has no key recovery or rotation. Never put the key or token in logs, process arguments, CI artifacts, or the repository.

## Test fixture

Install the offline dependencies from `requirements.txt`, `web/requirements.txt`, and `requirements-ops.txt` in the test environment. `requirements-ops.txt` is not part of the web runtime. Run unit tests with:

```text
python -m unittest tests.test_review_backup tests.test_review_backup_mongo -v
```

The two Mongo tests skip automatically if `REVIEW_TEST_MONGODB_URI` is unset. For a **separate disposable loopback replica set** named `codex-review-test`, created by the test runner, set the test variable to `mongodb://127.0.0.1:27027/?directConnection=true` and run the same command. Tests create synthetic UUID source/target databases and clean up only UUID databases they created; do not use `MONGODB_URI`. They check BSON/UTC/index and owner/key preservation after restore, existing-target rejection, wrong-key/tamper cases that must not create a target, and expired-record skipping. If restore fails midway, the test does not proactively delete a target whose successful creation has not been confirmed; the disposable container must be removed by the runner.

Fake tests check control flow only; they do not prove real MongoDB transaction behavior or durability. CI using a MongoDB replica-set fixture is evidence for that synthetic fixture only, not Atlas M0, production backup, RPO, RTO, or a real-user restore drill. This document does not record a synthetic live result unless it was actually run.

Completed addition: [CI run 41095342121](evidence/0.10/backup-fixture-ci-8f0afc0.json) at `8f0afc0` passed two real MongoDB restore tests within a 220-test suite (five raw-cache tests skipped). A synthetic source-to-target restore with different UUIDs preserved BSON/indexes/owner/key; a wrong key or modified token did not create a target, and expired records were not revived. The previous run at `77ad00f` failed because `list_database_names` does not accept the `filter` keyword; the code was changed to use the supported `list_databases` cursor without removing the test. This fixture receipt does not establish Atlas durability or production recovery time.

## Requirements before designing production backup

This primitive is restricted to a fixture; no production backup path exists. A production design must define MongoDB identity and permissions, the encrypted destination, key storage/rotation/recovery, retention and deletion, scheduling and monitoring, isolated restores, data-completeness checks, and a gate for promoting restored data to production. Permission to edit and deploy the web app already exists. If a design needs to export reviews to a new destination, add a credential provider, or incur costs, obtain specific approval for that new scope. Credentials currently remain limited to production Vercel. Recheck the availability and pricing of M0 backups before selecting a service.

An old snapshot cannot know that a user deleted a review after the snapshot was taken. Restoring it could make deleted data reappear while its expiry is still in the future. A deletion journal/tombstone or a verified deletion-reconciliation process is required before considering real data; expiry filtering does not solve this. This primitive does not reconcile deletions, confirm a restore, or establish RPO/RTO or production readiness.

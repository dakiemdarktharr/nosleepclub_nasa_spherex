# SPHEREx Mask Audit on Opened Data

The old policy allowed the FULLSAMPLE bit; SPHEREx documentation requires excluding that region from science. **None of the 31 WISE cutouts in use contains a FULLSAMPLE pixel**, so this policy error did not enter the fit through those cutouts. Effects on other fields or QR3 have not been checked.

The new policy separates pixels for source fitting from pixels for background statistics: SOURCE pixels may remain available when fitting a source, but are excluded when estimating a separate background. This does not mean SOURCE pixels must be removed from a joint source-plus-background fit. The background change has not been retested with the estimator; locked science products remain unchanged. Counts, official sources, and reproduction steps below are a development audit, not a new WISE measurement.

The previous WISE science mask and frame renderer both allowed the FULLSAMPLE flag, bit 12. The official [SPHEREx Explanatory Supplement v1.3, Table 10](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/SPHEREx_Expsupp_QR.pdf) describes this rotating 8 × 32 full-history region as unusable for science. The [IRSA source-discovery tutorial](https://caltech-ipac.github.io/irsa-tutorials/spherex-source-discovery-tool-demo/) also lists it among excluded flags. The [official pipeline flags](https://github.com/Caltech-IPAC/spherex-pipelines/blob/aa0ba446ee12971024fe13dc1c47387615bbe85e/py_src/spx_data/spx_flags.py) define FULLSAMPLE as `1 << 12` and SOURCE as `1 << 21`. The [IRSA QR2/QR3 help table](https://irsa.ipac.caltech.edu/onlinehelp/spherex/spherex/sp.html) lists both flags for both releases; its “yes” columns indicate availability, not that FULLSAMPLE is suitable for science.

The archived WISE coadd has **zero FULLSAMPLE pixels** across 31 QR2 cutouts (151,830 native pixels); zero pixels are legacy-good. Every individual exposure also has zero, including the independently defined linear-prior target regions: a 2.5-native-pixel radius (611 pixels total) and a ±5-pixel box (3,100 pixels total). Therefore this specific bit could not have entered the WISE fit through those 31 cutouts. This audit does not establish that the old policy is safe for other fields, unexamined exposures, or QR3. The prior is the pre-existing Luhman 2014 linear search position evaluated at IMAGE MJD-OBS. These regions do not include parallax or frame registration and are not fitted source positions. The zero count for the full cutout is stronger than either regional count but says nothing about data outside it. No source measurement was repeated.

The old science mask excludes its explicit BAD_BITS and also requires finite image values and finite positive variance. The old web display mask allows only zero, SOURCE, and FULLSAMPLE and requires a finite image, not variance; its output uses a nearest-neighbor resampled grid and an inside test. Native counts in the public report describe the equivalent per-pixel flag rule, not the number of rendered output pixels. The prior renderer source is identified by Git commit and SHA-256 independently of later runtime changes.

The proposed `science_mask_policy.py` is a new standalone conservative policy: target pixels may carry only SOURCE; background pixels must carry no flags. Both also require a finite image and finite positive variance. For these cutouts, the proposed target mask and old science mask each retain 147,238 pixels; the background mask retains 102,142. In the 611-pixel prior circles, 605 meet the old/target rule, but none meet the background rule because those valid pixels carry SOURCE. This background-policy change is separate from the FULLSAMPLE correction, and its downstream impact has not been measured. Do not silently substitute it into frozen products.

The policy accepts only explicitly labeled `spherex_qr2` or `spherex_qr3` L2 inputs with mandatory MP_* cards matching the checked pipeline layout. Additional MP_* cards must match verified names and bit positions, and every set image bit must be declared by that frame. Unknown, missing, duplicate, or mismatched definitions, negative/noninteger flags, and undeclared bits fail closed. The 31 audited headers are QR2 and contain two documented subsets of MP_* definitions. QR3 is supported only if the supplied header passes the same checks; no QR3 frame has been audited here. The allowlist is intentionally stricter than general-purpose IRSA photometry flags and does not itself establish scientific suitability.

Reproduce from existing cached inputs with `.venv\Scripts\python.exe scripts/audit_science_masks.py` and verify with `.venv\Scripts\python.exe -m unittest tests.test_science_mask_policy -v`. The [development audit](../web/data/mask-audit/development-audit.json) records the manifest and raw FITS SHA-256, URLs, per-exposure header definitions, WCS prior coordinates, counts for each region, and source hashes. Input hashes must match before counting. This is a descriptive audit, not new calibration, validation, source detection, or a revised WISE result.

# SPHEREx Observation Image API Contract, Version 1.1

`GET /api/frame` retrieves a cutout from an IRSA Spectral Image MEF—DR1, QR3, or historical QR2—and renders a PNG for **visualization**. Photometry and motion measurements require separate processing. The API accepts only HTTPS level2 product URLs on `irsa.ipac.caltech.edu` that match the official SPHEREx directory and filename structure. The input URL must be encoded and contain no query or fragment. [IRSA cutout instructions](https://caltech-ipac.github.io/spherex-archive-documentation/spherex-data-access/#cutouts-of-spherex-spectral-image-mefs).

```text
/api/frame?url=<encodeURIComponent(access_url)>&ra=350&dec=35&fov_deg=0.05&zodi=raw&low=0&high=2
```

| Parameter | Meaning |
| --- | --- |
| `url` | Required full level2 URL from IRSA for `dr1`, `qr3`, or `qr2`. |
| `ra`, `dec` | Required finite ICRS decimal degrees; RA [0,360), Dec [-90,90]. The frontend must convert sexagesimal first. |
| `fov_deg` | Minimum width of the square grid in degrees, >0 and ≤0.12; default 0.05. |
| `zodi` | `raw` by default, preserving IMAGE; `subtract` subtracts the per-pixel ZODI model when present. No local background is subtracted. |
| `low`, `high` | Optional, but both must be supplied; finite, `low < high`, within ±10⁹ MJy/sr. Pass the same range to every frame to compare intensity on a shared display scale. Omitting both uses independent 1st–99th percentiles for each frame, so brightness cannot be compared directly. |

PNG output is RGB on a common-center ICRS TAN grid, north up and east left, at 6.15 arcseconds per pixel. It uses the original FITS WCS including SIP and nearest-neighbor sampling. The number of pixels per side is the smallest odd integer that covers the FOV, with a minimum of 3 and maximum of 192. `X-Frame-Grid-FOV-Deg` reports the actual width, which is at least the requested width. This is a display grid: it does not add spatial resolution or correct astrometric offsets between exposures. The IRSA cutout is enlarged to cover the rotated grid; areas outside the image may still be missing. This sampling does not preserve flux, is unsuitable as a photometry input, and includes no uncertainty.

Usable pixels use a linear grayscale stretch after clipping to `low`/`high`. **Purple RGB (255,0,255)** marks pixels outside the image or with non-finite values. **Orange RGB (255,140,0)** marks pixels excluded by FLAGS. Policy 1.1 allows SOURCE bit 21 and masks every other bit, including FULLSAMPLE bit 12. Each image must have a FLAGS header identifying exactly those two bits. QR2 uses `MP_SOURCE=21` and `MP_FULLSAMPLE=12`. DR1 and QR3 use `MSKN0021=SOURCE`, `MSKM0021=2097152`, `MSKN0012=FULLSAMPLE`, and `MSKM0012=4096`. Missing, duplicate, or contradictory cards are rejected. If no pixels are usable, `X-Frame-Valid-Pixels: 0` accompanies a PNG that still reflects the mask and image boundaries. [Official IRSA flags](https://irsa.ipac.caltech.edu/onlinehelp/spherex/spherex/sp.html) · [Science mask audit](SCIENCE_MASK_AUDIT.md).

A 200 `image/png` response includes these headers:

- `X-Frame-Contract`, `X-Frame-Source-URL`, `X-Frame-Cutout-URL`, `X-Frame-Cutout-SHA256`, `X-Frame-Retrieved-At` (UTC): contract and provenance for the FITS cutout bytes actually received. This hash is not the hash of the full MEF file.
- `X-Frame-Release`, `X-Frame-Obs-ID`, `X-Frame-Detector`, and, when available, `X-Frame-MJD-Obs`: identifiers and time from FITS. The server checks that OBSID/DETECTOR match the URL filename. `X-Frame-Time-System: UTC` appears only when FITS declares `TIMESYS=UTC`.
- `X-Frame-Center-Wavelength-Um`, `X-Frame-Center-Bandwidth-Um`, and `X-Frame-Center-Spectral-Source: WCS-WAVE` when available. The server emits approximate center metadata only if the center pixel is usable and the alternate W WCS and `WCS-WAVE` table can be read.
- `X-Frame-Grid-RA-Deg`, `X-Frame-Grid-Dec-Deg`, `X-Frame-Grid-Scale-Arcsec`, `X-Frame-Grid-Size-Px`, `X-Frame-Grid-FOV-Deg`: shared grid and image dimensions.
- `X-Frame-Unit: MJy/sr`, `X-Frame-Zodi`, `X-Frame-Contrast-Mode` (`fixed` or `percentile_1_99`), `X-Frame-Contrast-Low`, `X-Frame-Contrast-High`, and `X-Frame-Valid-Pixels`: processing and display scale. If all pixels are missing, the percentile fallback is [0,1]; if both percentiles are equal, the range is expanded by ±0.5 MJy/sr.
- `X-Frame-Mask-Policy: source-only-allowlist-v2`, `X-Frame-Masked-Pixels`, and `X-Frame-Missing-Pixels`: policy and excluded/missing pixel counts on the PNG grid. Valid + masked + missing equals size². The frontend preserves the policy in JSON, shows the counts, and refuses to compare frames with different policies in the same search session.

WCS-WAVE at the field center is used to qualify display sequences. Measurement requires CWAVE/CBAND and the corresponding spectral calibration. Frames from different times may have different bandpasses, calibration, PSF, background, and coverage. [IRSA data products](https://caltech-ipac.github.io/spherex-archive-documentation/spherex-data-products/).

IRSA cutouts use `center` and `size` as described in the [service instructions](https://irsa.ipac.caltech.edu/ibe/cutouts.html). FITS size is limited to 12,000,000 bytes; native images are capped at 512×512. The socket timeout is 20 seconds and the deadline is 80 seconds, checked between reads; a pending read may take up to 20 additional seconds. Vercel `maxDuration=120` is recommended to allow for cold start and processing. According to [Vercel limits](https://vercel.com/docs/functions/limitations), Hobby requires Fluid compute for this setting (without Fluid, Hobby allows at most 60 seconds). Verify the actual deployment configuration; do not change the plan automatically. The runtime requires `astropy==8.0.2`, `numpy==2.4.6`, and `Pillow==13.0.0`. The local static Python server does not run this serverless API.

Directory and FITS filenames may use an `l2b_retry-v…` version. They must match each other and the same planning period and detector as the Level 2 path. The API creates a cutout query only after the input URL passes this validation. [Official IRSA notebook](https://caltech-ipac.github.io/irsa-tutorials/spherex-cutouts/).

On 30 October 2026, a QR2 D6 exposure at RA 350°, Dec 35° returned a 5,094,720-byte cutout in 3.27 seconds. The HTTP handler produced a real PNG in 2.94 seconds; cutout SHA-256: `5479f905947fe3703a092f812abaca4235ca5723aa07a5da6a8d78bb6dedff21`. After a fix, the next exposure returned a real PNG through the handler in 3.12 seconds; cutout SHA-256: `2ca7b4bf2ab7a4e7ae7309745b6b7adfcf8172363f533b524d0aa7a6503ba0d4`. Other calls returned HTTP errors or had interrupted streams after 47.06 seconds; this is not a latency or availability guarantee for Vercel. IRSA states that SPHEREx cutouts retain all extensions. Do not remove PSF data or use a partial FITS file, which would change provenance. An interrupted stream or incorrect Content-Length returns an error and does not create a PNG. A 300-second public cache may reduce load for identical URLs when the cache layer supports it; a cache hit is not guaranteed.

Invalid requests return JSON 400; commonly unsupported methods return 405; upstream/FITS errors return 502; timeout returns 504; internal errors return 500. Stack traces are not returned. The production rate guard uses MongoDB: 8 requests/IP/minute and 24 globally/minute. Exceeding a limit returns 429 and `Retry-After`; missing valid environment/identity/storage returns 503 before calling IRSA. The [guard contract](API_ABUSE_CONTROLS.md) describes XFF and local test mode. Browser/CDN cache is at most 300 seconds; errors are `no-store`, and FITS is not cached in the database. Retrieval timestamp/hash belong to the cached response. Logs use an allowlist of request ID/status/category/latency/severity. Frame errors include an error code and upstream HTTP status when available, but not URL, coordinates, body, cookie, or secret.

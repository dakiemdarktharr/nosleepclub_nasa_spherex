# Native-Pixel Physical Gain Audit

The UUID in the headers of 31 WISE cutouts was matched to the corresponding IRSA QR2 D6 gain file. **30/31 images have positive gain at every target-mask pixel**; the remaining image has one negative-gain pixel with no flag, about 20.21 pixels from the old prior and outside the ±5-pixel prior box. This is not a refitted position; its effect on the scientific result is unknown.

Units, UUID, and hash were checked. Gain orientation is an inference conditional on public R6 snapshots: use WCS A to read `gain[y,x]`, without another flip. The gain file does not specify DETCOORD, and the exact image-build sources were not found. The binder rejects nonpositive gain; no photon-noise injection or source remeasurement has been performed. This record preserves the technical limits and references for further review.

This audit binds one archived QR2 D6 absolute gain file to the 31 previously cached WISE cutouts, conditional on the orientation inference below. It does not inject source noise, refit positions, validate accuracy, or certify a production calibration.

The IRSA TAP response `data/raw/benchmark/calibration-uuid-lookup.xml` maps `0b762d1b-bec8-473f-9e6e-436fff6c631f` to the [D6 absolute gain FITS](https://irsa.ipac.caltech.edu/ibe/data/spherex/qr2/abs_gain_matrix/cal-agm-v7-2025-218/6/abs_gain_matrix_D6_spx_cal-agm-v7-2025-218.fits), with product type calibration, product ID D6, and provenance version 6.1. Each of the 31 IMAGE HISTORY headers names that exact UUID once. The complete TAP query, cached-response SHA-256, URL, file SHA-256 and byte count, and calibration headers are in the [audit JSON](../web/data/native-gain/development-audit.json). The downloaded file is 16,652,160 bytes, SHA-256 `b297b1f286cd66b0ce109c5cb884ab08ca980376edf9f161cbf9cd754674bdb8`, shape 2040 × 2040, software version `6.1.3.post97+g4430725`, and BUNIT `MJy s / (electron sr)`, consistent with the [IRSA product description](https://caltech-ipac.github.io/spherex-archive-documentation/spherex-data-products/).

The calibration file itself does **not** identify DETCOORD or contain a WCS. The cutout IMAGE headers specify `DETECTOR=6`, `DETCOORD=sky`, and alternate WCS A named `0-based active pixel coordinates`. The [public R6.4 pixel-removal module](https://github.com/Caltech-IPAC/spherex-pipelines/blob/d31bc5a6666b4530c6e233c2484c586b4a598b24/py_src/spx_tasks/remove_reference_pixels.py) sets the active-pixel WCS and reverses detector 4–6 images on X; its [WCS helper](https://github.com/Caltech-IPAC/spherex-pipelines/blob/d31bc5a6666b4530c6e233c2484c586b4a598b24/py_src/spx_utils/alt_wcs.py) defines this A system with zero-based active coordinates. The [R6.4 calibration module](https://github.com/Caltech-IPAC/spherex-pipelines/blob/d31bc5a6666b4530c6e233c2484c586b4a598b24/py_src/spx_tasks/apply_dark_flat_field_and_photo_calib.py) then multiplies the image directly by the gain array; the same direct operation appears in [R6.5.5](https://github.com/Caltech-IPAC/spherex-pipelines/blob/aa0ba446ee12971024fe13dc1c47387615bbe85e/py_src/spx_tasks/apply_dark_flat_field_and_photo_calib.py). The cutouts record the same module document version, v1.5, but their exact `6.4+psffix1` and `6.5.6` builds were not found in the public repository. Therefore, using WCS A `(x, y)` as `gain[y, x]` with **no additional flip** is an inference from public snapshots and recorded processing, not an orientation asserted by the gain FITS metadata or verified exact-build code. Independent official confirmation would close this gap.

The proposed binder is restricted to this file, UUID, known hash and size, QR2 D6, the two observed image versions, the verified exact FITS header layout, and an identity-oriented linear WCS A. It requires native integer pixel coordinates, an in-bounds active-detector index, and finite positive gain for every requested pixel. Unknown layouts, missing/conflicting metadata, wrong units, noninteger positions, invalid indices, or invalid gain fail explicitly. It does not infer a flip or interpolate gain. The strict science target mask separately requires finite image and finite positive variance and permits only zero or SOURCE flags. The frozen pipeline and masks are unchanged.

Of 31 cutouts, 30 have positive finite gain at every strict-target-mask pixel; the remaining cutout is partially unsupported. The exceptional pixel in `2025W46_1A_0090_3` has native `(x,y)=(41,15)`, active `(932,1277)`, gain `−5.05665445`, IMAGE `−18.91776085 MJy/sr`, VARIANCE `15.71095371 (MJy/sr)²`, and FLAGS `0`. Adjacent gain values are near 0.39–0.43. This co-located image/variance anomaly is consistent with signed gain multiplication and squared variance scaling; it does not independently prove orientation. Public v1.5 processing passes the original flags through and has no visible gain-positivity check. The new binder rejects this pixel; it never substitutes or silently discards its value. Descriptive gain quantiles for remaining positive pixels in that exposure are labeled in JSON as a partial subset.

For each exposure, the report gives gain quantiles and the corresponding positive-gain coefficient `P(n) × gain / (n × TSAMP)` in gain per second, so multiplying by source surface brightness gives ideal source-only variance in squared brightness units. Here `n=SURLIM-(SURDLY-1)` and `P(n)=6/5 × (n²+1)/(n²−1)`; the previously developed ideal-ramp timing checks also verify XPOSURE against `(n−1) × TSAMP`. This is a coefficient, not a measurement or simulated draw. It excludes source PSF/SED truth, partial ramps, read noise, nonlinearity, crosstalk, and gain uncertainty. Before any photon injection, lock an independent source/PSF/SED and noise protocol.
